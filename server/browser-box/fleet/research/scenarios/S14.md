# S14: the Stagehand extension is detectable on a logged-in identity

Scenario: M1 measurement shows Stagehand v4's resident extension trips automation checks on a logged-in identity.
The decision: switch L1 and L2 to a minimal CDP executor, keep Stagehand for L3 `extract` on the open web. Cover
the impact on skills and docs.

Role: scenario stress-tester. Nothing here is built. Every statement about a product cites a path or is marked
`estimate` or `to measure`. No timelines are given.

**Verdict: handled-with-gaps.** The design expected this outcome: D6 says executor choice is made in M1 "per site
class" and ARCHITECTURE §4.3 puts L1/L2 behind an `Executor` interface. So the switch is allowed. But the switch is
much larger than "swap L1/L2". The Stagehand extension is the whole engine, not just an executor. Snapshot, xpath
map, `act(Action)`, `observe` and `extract` all run inside it (`docs/engines/stagehand.md` §2). Turning it off on
logged-in identities removes L3 there too, and removes the format the L1 cache is stored in. The minimal executor
is only a "test harness" in M1 and a single build row ("L2 executor wiring") in M3. That mismatch is the main
finding.

---

## 1. Premise check

1. **M1 cannot measure a real logged-in identity.** G1.4 runs "against the public detection pages the earlier spikes
   used, including `isAutomatedWithCDP`" (`MILESTONES.md` G1.4). Real platforms are forbidden in spikes
   (`docs/engines/stagehand.md` status ledger, L91: real social sites "not tested, forbidden in spikes"). So "trips automation
   checks on a logged-in identity" can only mean: a detector page trips on a logged-in persona's Steel session.
   Whether a platform weighs that signal is **unknown** (`MILESTONES.md` R-11; `research/verification/antidetect-proxies.md`
   AP-2). The practical read of the scenario: G1.4 shows a trip, no mitigation removes it, and policy says do not
   take the risk on accounts.
2. **What was measured.** AP-2 is n=1, with a **CDP-loaded** extension on stock Chromium 152. The fleet loads it with
   `--load-extension` through Steel's `extensions:["stagehand"]` (`docs/engines/stagehand.md` §13.2; `docs/engines/steel.md`
   §9.1 around L538). A flag-loaded extension may behave differently. G1.4 is the test that tells.
3. **Uninstall.** The documented mitigation is `Extensions.uninstall` after the session. That is "untested on Steel
   for a flag-loaded extension" (`docs/engines/stagehand.md` §13.4). If it works, S14 shrinks to a mitigation. This
   walk assumes it does not, because otherwise there is nothing to decide.
4. **Branch.** Under Branch A (API-first, the default; Q-01 pending) the browser mostly does the login probe,
   read-back, and the narrow no-API set. Under Branch B (browser-first) it does most of the work. The size of S14
   depends on that branch (section 5).
5. **The signal may not be the extension alone.** `Runtime.enable` and `Target.setAutoAttach{waitForDebuggerOnStart}`
   are the likely causes (AP-2). The fleet's own Guard also uses browser-wide `Fetch.enable` and
   `Target.setAutoAttach` (`gateway/gateway/guard.py`). So a "minimal" executor may trip the same check through the
   Guard. Nobody has measured the Guard alone (`MILESTONES.md` G1.4 lists three executors, not the stack).

## 2. What Stagehand's extension carries today

The engine is the extension (`docs/engines/stagehand.md` §2): the MV3 service worker holds the snapshot builder, the
`xpathMap`, `act(Action)`, `observe` and `extract`. Its content script runs in all frames at `document_start`. The
fleet uses it for these things; each one goes away with the extension:

| Stagehand function | Used by | Fleet dependency that breaks |
|---|---|---|
| Snapshot and `xpathMap` | L2 candidate list, L1 fingerprint check, evidence | ARCHITECTURE §4.3 L1: "re-snapshot, verify role, accessible name, frame path". The verifier has no snapshot source |
| `act(Action)` with `selfHeal:false` | L1 replay | The cache stores Actions "not instructions" (D5; `l1_entries`, ARCHITECTURE §3 L617). The Action format is Stagehand's |
| `observe` | L3 on logged-in sites, the "split, don't fuse" rule (`docs/engines/stagehand.md` §5.7: observe, verify, then `act(Action)`) | L3 on accounts |
| `extract` | Tier 1+ on accounts; lead-gen reads | `extract` on logged-in sites |
| `ignoreLocators` | DM and private-region redaction before any model call (`docs/engines/stagehand.md` §6.2 item 13 around L645, L731) | The Q-07 default (do not send DMs to a model) has no enforcement |
| Forbid-mode shim | Proof that L1/L2 make zero model calls (`docs/engines/stagehand.md` §6.3, L652; G3.3) | The proof is Stagehand-specific |
| Frame and shadow-DOM handling | Composer inside iframes | Untested for any other executor (G1.4 lists it as "also run") |

Not affected: Steel (the host), the Guard, the forwarder, the shim, effects and approvals, Browser-Use (separate
engine), L0 (API), L5 (human).

## 4. L3 on logged-in identities, now with no engine

D5 defines L3 as "Stagehand with GLM 5.3 Flash via the shim". With the extension off on `account` identities, L3
there has three possible forms:

| Option | What it is | Cost | Risk |
|---|---|---|---|
| A. Fleet **L3-lite** | The fleet's own snapshot builder, a shim call with the schema `{elementId, method, arguments}` (the same schema L2 uses, `docs/models/system1.md`), gate G, then the minimal executor | New code: snapshot builder, prompt, schema, bench. Reuses the shim and gate | Quality unknown until benched (G3.5 covers Stagehand only). Per-call tokens unknown (`to measure`) |
| B. Climb to L4 | Browser-Use `task` with a conservative action set. Browser-Use's attach/navigate/state did not trip (AP-3); its actor API and coordinate click do | Few new components | More steps and more model spend than L3. Browser-Use's own click path is not the minimal executor; whether a normal element click through its default action set trips is **untested** ("behavioural click/type was not tested", AP-3). The Browser-Use docs lean on this (`docs/engines/browser-use.md` ~L843) |
| C. Climb to L5 | A person does the step in the viewer | No build cost | Human load rises with every L1/L2 miss. The ladder's economics (D5 System-1 share, the 7-8% figure in the skills) are estimates that assumed Stagehand L3 would absorb misses |

Recommendation: A, scoped by Q-01 branch. Under Branch A, accept L5 for misses (the no-API set is small). Under
Branch B, build L3-lite, because the ladder's cost case depends on it. In both cases re-estimate the System-1 share
and human load before M3's gates are claimed. The estimates are marked `estimate`, not measured, in ARCHITECTURE.

**Research identities are unchanged.** Stagehand stays for L3 `extract` on the open web (kind `research`, no login).
This is the part of the scenario that works as written: `research` identities may keep `extensions:["stagehand"]`
(mode A) because there is no account to burn. Open-web sites do run bot walls, and a detectable extension may raise
the challenge rate (`to measure`: yield of `research` identities with and without the extension; add to G1.4).

## 6. What the switch breaks or leaves unspecified

1. **No production executor exists in the plan.** The minimal CDP executor is a G1.4 candidate ("test harness only")
   and the M3 row is "L2 executor wiring". No acceptance criteria, no owner, no language. AGENTS.md (L162) says
   "Stagehand worker (Node)" while ARCHITECTURE has Python by default. A minimal executor is a new codebase of its
   own that the fleet must maintain against Chromium changes.
2. **The `Executor` interface is undefined** (ARCHITECTURE §2.3 L203, §4.3 L790, L1659). It is the seam the switch uses and nothing
   defines the Action schema, the snapshot shape, the frame path, or the post-action check. `l1_entries` rows have no
   `executor_id` or `schema_version`, so a changed executor makes the cache silently stale or wrong (R-13 is the
   wrong-click risk).
3. **Extension on every wake** (ARCHITECTURE W8/W10, N2) contradicts steel.md §9.1 and steel-profile L64. `extension_mode`
   is a per-wake argument "not part of the persona" (steel-profile L329) with no rule for who sets it.
4. **Account images carry the extension and its flags.** Steel's image holds the extension directory (N2), runs with
   `--remote-allow-origins=*` and the two `DisableLoadExtension*` feature overrides (steel-profile L290, steel.md L532),
   and has `forwarder rule 9` so the extension can reach CDP. On an account identity with no extension, none of that
   is needed. Leaving it in place keeps the `--load-extension` capability and the open WebSocket origin for no
   benefit (this also bears on S13 gaps S13-6, S13-8). Whether the feature overrides themselves are a signal is
   `to measure`.
5. **G1.4 measures executors in isolation.** The fleet's real stack adds the Guard, the persona check via
   `Runtime.evaluate`, the login probe, the exporter, the viewer screencast and input, and a headless/headful
   choice, all through a proxy. G1.9 (host comparison) has no detectability arm. A minimal executor that is clean
   alone may trip once the stack is attached.
6. **No outcome is defined for "no executor passes" or "results are mixed".** G1.4's selection rule picks a winner
   among executors; if every candidate trips on the logged-in persona, nothing is written. Each outcome must be
   named: API-only plus `human_clicks`, owner acceptance in writing (risk register), or the MK fallback.
7. **Executor identity is not pinned.** `identities.image_cohort` covers the Steel digest and Chromium major
   (ARCHITECTURE §3.2 L372). It does not cover which executor or extension mode an identity runs. Moving an identity
   from Stagehand to the minimal executor changes its observable behaviour and DOM footprint, and is a persona change
   that should go through the canary rule (O-13). Moving back and forth per wake is worse.
8. **Privacy enforcement vanishes silently.** `ignoreLocators` is the only enforcement of the Q-07 default (DMs
   never reach a model) and the secret-field rule on composers. The fleet's snapshot builder must reimplement it,
   with a test, or the first L3-lite call leaks a DM thread into a prompt.
9. **Gates tied to Stagehand.** G3.3 (`selfHeal` verified false), G3.7 (adversarial corpus run through Stagehand),
   the forbid-mode proof, the S1 launch-flag smoke test (`--remote-allow-origins`, `DisableLoadExtension*`), and T11
   in steel-profile all assume the extension. Each needs a restatement for the minimal executor or a replacement.
   A structural replacement for forbid-mode: "the executor process imports no model client" plus a **CDP-method
   allow-list** test that records the methods the executor sends and fails on anything outside the list.
10. **Skills and docs name the engine.** Section 7.

### 6.1 Decisions that need amending

- **D5** defines L3 as Stagehand. Amend: L3 is "a model call that chooses among structured candidates, executed by
  the identity's executor". Stagehand is one implementation.
- **D6** makes Stagehand the main engine and defers executor choice to M1. Amend: executor by identity kind
  (`research`: Stagehand allowed; `account`: the minimal executor unless G1.4 shows otherwise), with a site-class
  override recorded in the router. Keep Browser-Use as the open-ended fallback.
- **D4/N2** (image contents) and **W8/W10** (wake) follow from that.

None of these conflicts with an invariant. CHARTER invariants 6 to 9 (effects, approvals, no hidden writes,
fail-closed gating) are enforced outside the engine.

### 6.2 A side benefit (design idea, `to measure`)

Without the extension on account identities, rule 9 (the forwarder accepting a CONNECT to its own bridge IP:3000)
is not needed for them, nor is `--remote-allow-origins=*`. That removes the in-page path to Steel's unauthenticated
API discussed in S13 (S13-6) and makes a uid-based loopback rule feasible if variant N and a uid-dropping Chromium
wrapper are chosen (Q-08). Neither is tested.

## 8. Failure branches

| Branch | Trigger | Result | What is needed |
|---|---|---|---|
| F1 | The minimal executor is clean in isolation and trips in the stack | The Guard or the viewer is the cause | Test the stack (G1.4 as amended). Mitigations: reduce Guard scope, use the proxy-level block as the first layer, measure |

| F3 | Every executor trips | No logged-in browser automation on that site class | Branch A: API-only plus `human_clicks` through the viewer. Branch B: this is a product decision: owner acceptance in writing, or hold the site class (MK fallback) |

| F5 | The minimal executor's behavioural input (click timing, mouse path) is detected | Needs a human-like input layer | Out of scope for the drafts; a new component and a new risk |
| F6 | The L1 cache was built on Stagehand Actions before the switch | Entries unreadable | Version the key; rebuild on first use; do not convert |
