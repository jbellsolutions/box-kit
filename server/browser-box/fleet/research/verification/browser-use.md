## Unsourced or mis-sourced numbers in the dossier

1. **"Jev's ~180" option cap** (Verdict 2, and RESULTS calls 255 "Decider's" cap). Jev's API rejects 256 options and accepts 255 (measured 2026-10-10). 180 is jev-automation's client `MAX_ELEMENTS`.
2. **"Defaults ... 2.7x the cost per task."** It divides by the cheapest single baseline run. Against the baseline mean it is 1.65x cost and 1.71x tokens.
3. **"Cookies written <30 s before release were lost" / "wait ≥30 s".** Only 2 s and 40 s were measured, n=1 each. Chromium's `kCommitInterval = 30 s` supports the number but is not cited.
4. **"Action schema: about 14 KB, sent every step."** No measurement is recorded. A static build gives 17.3 KB (normal), 16.7 KB (flash) and 13.4 KB (flash with 3 actions excluded). The raw flash runs bill about 3.5k prompt tokens per step while the messages alone are 10.6k chars. So GLM's providers do not appear to bill the schema as prompt tokens, which makes "token driver" doubtful for this model.
5. **"GLM at max effort (~40 s/step)"** (patch table). No source or measurement in this dossier.
6. **"168 open issues on 2026-10-10" and "at least 23 closed by the 14-day stale bot."** No query is recorded. Search API at about 14:30 UTC: 169 open; 31 closed issues carry the `stale` label. The stale bot (`.github/workflows/stale-bot.yml`) marks issues stale after 60 days and closes them 14 days later. It is not a "14-day" bot.
7. **"message compaction (every 25 steps or about 10k tokens)."** Source requires both conditions: ≥25 steps since the last compaction **and** ≥40,000 chars of history (`message_manager/service.py:235-242`).
8. **"Remote sessions still get a temp `user_data_dir` (hands-on `pure_checks.json`)."** `pure_checks.json` has no such entry. The real evidence is in `persist1.err` (a `user_data_dir=/var/folders/.../browser-use-user-data-dir-*` warning) and `conc1.err` (pending `monitor_storage_changes` tasks).
9. **"$0.000115 per decision"** is presented as a constant. It is the cost at 71 options; at 255 options it is $0.000363 (measured).
10. **Steel image `7a161b95e8a9`** and the live container's "openai 2.26.0 / browser-use 0.13.10" (from a `docker exec`). Both are unverifiable here: re-checking them needs Docker, which this round does not touch.

## Missed issues

1. **Detectable DOM injection on every click and type.**
   - `highlight_elements=True` is the default (`profile.py:697`). `highlight_interaction_element` then injects `<div data-browser-use-interaction-highlight="true">` at `z-index: 2147483647` into the live page via JS (`session.py:2940-2995`).
   - It is called from `click`, `input` and `upload_file` in `tools/service.py:728,793,936`, so it also runs on the System 1 `Tools.act` path.
   - Any social site with a MutationObserver can see it.
   - The dossier lists `highlight_elements=True` as a default without flagging the risk. Its fleet defaults, and browser-box's runner, do not turn it off.
   - Fix: set `highlight_elements=False` (and keep `dom_highlight_elements=False`) in the fleet's profile.
2. **The author's own proxy probe does not support the "proxy ignored" wording, and the dossier never reports it** (BRO-11). The probe recorded `proxy_ignored: false`; its cause is unexplained.
   - Side effect the dossier missed: giving Browser-Use proxy credentials on a remote session turns on Fetch interception of every request on the focused tab (`urlPattern: '*'`).
   - Keep all proxy configuration and credentials in Steel's `proxyUrl`.
3. **The Q4 attach sample implies per-profile paths that self-hosted Steel ignores.** It shows `httpx.post(".../v1/sessions", json={"userDataDir": "/profiles/p1", ...})`, but any `userDataDir` value maps to one fixed directory (`session.service.ts:180-183`). Implementers copying the sample will cross-contaminate profiles unless each profile has its own container or volume.
4. **Every dollar figure is confounded by OpenRouter provider routing.**
   - The same GLM tokens cost $0.00066 per step on InferenceNet and $0.0013 on Together. Per-task costs vary 2x for identical work.
   - For a fleet budget, pin providers (OpenRouter `provider` routing) or budget on tokens.
   - Note that `ChatOpenRouter(extra_body=...)` needs 0.13.11 (BRO-7).
5. **Cookie-loss mechanism left open.** Steel's release awaits `close()` and then calls `process().kill()` (`cdp.service.ts:520-521`). Whether Chromium got a graceful profile shutdown, which flushes the cookie store, is untested. With constant cookie writes on social sites, "wait 30 s" is not a guarantee. A graceful-flush release, or Steel's `sessionContext` capture, needs a droplet test before persistence design is final.
6. **The decider's accuracy evidence is thinner than "2/2" suggests.**
   - 5 Jev calls were made. Only 2 runs completed with a recorded outcome.
   - `direct_dbg` chose `e6`, which the recorded output cannot map to a label.
   - My independent call on HTML-derived candidates (75 options) also chose Poetry (0.98). That supports the claim, but it is still one easy page.
7. **The "temp `user_data_dir`" behaviour is mis-cited, and its effect is narrower than implied.** With `storage_state=None` the watchdog polls `Storage.getCookies` every 60 s but writes nothing (`storage_state_watchdog.py:164-166`). It does leave an empty `browser-use-user-data-dir-*` temp directory on the worker host for every session, which accumulates at fleet scale.
8. **Minor: flash mode is model-dependent.** For Anthropic 4.5 models it selects a 21 KB `system_prompt_anthropic_flash.md` (`prompts.py:73-74`), so "flash = 2.4 KB" holds only for non-Anthropic models such as GLM.
