## Missed issues

1. **Lease SQL cannot do takeover and breaks fencing on renewal** (SCA-10). Reproduced locally. The human-login requirement depends on this primitive.
2. **A catch-all fallback can duplicate effects** (SCA-8): any exception from a whole-workflow call (including a failed or timed-out run that already produced effects) re-runs the job through asyncio. The dossier only describes the "Temporal unreachable" case and calls it silent; it logs a warning.
3. **No soak test for long active sessions.** The spike ran ~70 s per browser. The README documents Chromium memory climbing with use and a whole-server crash on an unhandled rejection. 3 h/day per profile is the load the 1.5 GiB cap, the 7-slot figure and the "idle reaper" were never run against. Needs an idle-restart policy (restart Chromium at a memory threshold) in the node agent design.
4. **Wake-latency figure leaves out the network-bound steps** (SCA-6): bundle download/decrypt/extract, proxy connect, IP-echo check, fingerprint check, and node creation (DO: 60 s billing minimum, at most 10 droplets created at once, snapshot-based boot).
5. **DO v5 droplets and Autoscale Pools** are not discussed (SCA-12). The 672 h cap and the $96 price apply to bundled plans only; v5 is $0.1953/h for the same shape with no cap, in datacenters that support it.
6. **Steel Cloud as the "paid backup" lacks stealth below Enterprise** (SCA-13). The cost comparison prices Steel Cloud Scale against self-hosting as if it were feature-equivalent for social sites; the pricing grid says Stealth browser is Enterprise-only.
7. **Cheaper vendor plans were skipped** (Browserbase Developer at 30 x 1, Steel Launch), which moves the 30-profile comparison (SCA-11). Does not change the recommendation.
8. **The effect-ledger receipt for real social platforms is unproven** (SCA-9). The reused pattern verifies against a controller-owned synthetic CRM. How often a post or DM cannot be read back (delayed feed, shadow-ban, DM requests folder) decides how many effects land in `uncertain`, i.e. human work. This is the highest-risk assumption in Q3 and has no spike.
9. **Temporal workflow-ID dedupe is overstated** (SCA-9): needs `REJECT_DUPLICATE` and retention to hold after completion.
10. **A no-fork route to a stable fingerprint exists** (SCA-3): pin `userAgent` + `dimensions` + `timezone` (+ `skipFingerprintInjection`) in the REST body and inject from the node agent over CDP, so "ship a patched Steel image" is one option, not the only one. Quality/realism of either is for the antidetect dossier (the E3 run still shows `screen` 800x600 and SwiftShader).
11. **Context checkpoint is better than described but less tested** (SCA-15): Steel's export format already carries sessionStorage and IndexedDB (the dossier says IndexedDB does not travel), and the 5-vs-6 cookie difference in the raw data is an expired cookie, not a filter. The restore test used one marker cookie and one localStorage key.
12. **MCP timeout for the no-code integration route is 90 s, not the 300 s default** the dossier cites (hermes-packaging verification HP-5: a plugin-less host writes `timeout: 90`). It strengthens the submit-then-poll advice; the "300 s" sentence should be qualified.
13. **Stagehand-on-GLM tail risk**: 2 of 24 low-effort Stagehand rows ran to 8,000 completion tokens. A per-call output cap and a cost guard belong in the gateway, not just a per-day spend alert.
14. **Units**: GiB/TiB/TB are mixed in the headline ("1.85 TB"), and one README MiB figure was divided by 1,000 (1.36 vs 1.32 GiB). Cosmetic, but these are the numbers a reader will quote.
