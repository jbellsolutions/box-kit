# Gemini claims audit

Date: 2026-10-10. Audited file: the original Gemini conversation export (944 lines, 8 turns; not included in this repository because it is a third-party chat export). Role: Gemini claims auditor for the System 1 browser fleet research. The Gemini file is a hypothesis list, not a source (BRIEF.md). Each claim below was checked against the fleet dossiers and adversarial verification reports, and against public pages and APIs where the dossiers are silent.

**Method and limits.** No browser, Docker container, Docker network, Hermes CLI, keychain, sudo or push was used. Everything was done from source, docs, saved spike results, public HTTP calls (docs, Hugging Face and OpenRouter catalogs, vendor pages, one unauthenticated POST to each of two hosts) and offline Python introspection of the installed packages (`python -I`, no network, no browser). Any check that needs a browser or a container is marked unverifiable (needs hands-on on a droplet). No secret was read or printed.

## Summary: how much held up

I extracted **124** specific factual claims (API and call shapes, features, prices, latencies, percentages, model names, code samples, case studies). Verdicts:

| verdict | count | share |
| --- | --- | --- |
| confirmed | 33 | 27% |
| partially confirmed | 48 | 39% |
| wrong | 26 | 21% |
| unverifiable | 17 | 14% |

Roughly one claim in 4 survived untouched, and one in 5 is flatly wrong. The shape of the failure is consistent:

- **What held up:** the architecture (separate the router from the execution sandbox), the Stagehand-versus-Browser-Use roles at a high level, the idea that decision models only choose and cannot extract, the Steel Cloud Python SDK shapes (`sessions.create(profile_id=..., persist_profile=True, use_proxy={...})`, `session_viewer_url`, `release`), the 30-day profile expiry, one dedicated ISP proxy per account, the E2B Desktop method names, most of the Cua and Cua Spaces description, Steel being model-agnostic, and the `router.py` and SQL samples (they run).
- **What did not hold up:** every Stagehand call shape (`env="BROWSERBASE"`, `cdp_url`, `init()`, `.page`, `extract(schema=)`) raises on the installed 4.2.0; the selector-cache premise ("leads 2 to 1,000 cost $0") is false on Steel; Steel Cloud features (Profiles, `useProxy`, CAPTCHA, stealth, 1,000-way concurrency) are attributed to the self-hosted Steel the user actually runs; the Jev endpoint `api.typesafe.com/v1/jev/decide` does not exist; the System 1 price range, the 0.85 threshold and the 70% savings are unsourced or wrong; "browser-use uses LiteLLM / LangChain" is false; "under 50 ms" is an API enqueue time; the Hyperbrowser and Browserless rows are wrong; Claude 3.5 and 3.7 Sonnet are retired; the social-account blueprint ignores platform terms; the Redis lock sample is a no-op.
- **Root causes:** (1) Gemini treats Steel Cloud and the OSS steel-browser as one product, and the user runs the OSS one (no Steel Cloud key exists). (2) It describes Stagehand v3-era behavior (cache, `init()`, `page`) under a v4 name, and invents shapes that never existed. (3) Its numbers (50 ms, 90%, 70%, 0.85, $0.00, cost per task) carry no source, and where measurable they are off by a large factor. (4) It is blind to terms of service.

## The ten most consequential errors

1. **Stagehand call shape is not real (rows 2.10, 10.01-10.05).** `Stagehand(env="BROWSERBASE", cdp_url=..., model_name=..., model_client_options=...)`, `init()`, `.page` and `extract(schema=...)` fail on 4.2.0 (`TypeError: ... unexpected keyword argument 'env'`). The real v4 shape is `Stagehand.create(browser=await local_browser.connect(cdp_url=...), model=<callback or provider/model>, self_heal=False)`; attaching to self-hosted Steel also needs the extension in the container and `extensions:["stagehand"]`.
2. **The "cached selectors, $0 replay" premise is false on Steel (rows 2.05, 11.02).** The v4 cache is Browserbase-server-only and shows DISABLED on Steel; v3 `cacheDir` keys on URL + instruction (1,000 different sites never hit) and was observed replaying a click on the wrong element with `success:true`. Charter principle 3 and the whole cost model rest on this.
3. **Steel Cloud features credited to the user's self-hosted Steel (rows 4.05, 4.10, 4.11, 4.15, 4.16, 9.01, 10.10).** Profiles, `persistProfile`/`profileId`, `useProxy`, CAPTCHA, stealth, timeouts and the 1,000-way concurrency are Cloud-only. Self-hosted Steel strips the fields with HTTP 200, runs one browser per container, has a fixed `userDataDir` and an unauthenticated control plane. "Standardize on Steel.dev because you already built on it" confuses the two.
4. **Invented Jev endpoint and request shape (row 10.06).** `POST https://api.typesafe.com/v1/jev/decide` with `selected_index` does not exist (the host does not resolve). The real call is `POST https://api.typesafe.ai/v1/systemone` with `{model, state, questions:{id:{type, instructions, criteria}}}`, answers keyed by question id, and a 1 s timeout that is too tight (jev-automation uses 8 s for decide and 6 s for verify).
5. **System 1 economics and thresholds are unsourced or wrong (rows 6.03-6.08).** Real prices are $0.02 to $0.24 per million tokens, not "$0.00 to $0.02"; a realistic 180-candidate step is 5k to 6k tokens, so "near-zero" cost per step is also wrong; confidence is not portable (the same weights gave 0.43 versus 0.74 on two hosts); ">0.85" and "-70%" have no basis in any measurement.
6. **"browser-use uses LiteLLM / LangChain" and the sample that follows (rows 3.02, 10.07).** browser-use has its own LLM protocol and is pure CDP; langchain-openai is only an examples extra. `Agent(llm=langchain ChatOpenAI, browser=<Playwright Browser>)` cannot run: `llm` must be a browser-use chat model and `browser` a browser-use `Browser`/`BrowserSession`.
7. **Persistence and identity are overstated (rows 4.03, 4.05, 5.04, 1.04).** Steel profiles do not persist "canvas/hardware fingerprints permanently": OSS regenerates a flawed random fingerprint on every launch, and Cloud deletes profiles after 30 idle days (Gemini says both). Browserbase has no sticky IP, no Context export and Linux-only fingerprints below Scale. A cookie set under 30 s before release is lost.
8. **"Under 50 ms" browser spin-up (row 11.01).** That number is browser-use's API returning HTTP 202 after queuing a task. Measured on self-hosted Steel, browser readiness is 6.5 to 11 s to create on a restored profile and 15 to 20 s for a cold wake (Browserbase and Steel Cloud latency was not measured; no keys exist), and Chromium cannot launch in 50 ms.
9. **The social-account blueprint ignores terms of service and ships a broken lock (rows 9.02, 9.03, 10.13).** X bans non-API automation with permanent suspension, Meta bars automated access, LinkedIn messaging needs a member action, TikTok rejects internal upload tools, and Steel's own terms bar violating sites' terms. The mutual-exclusion step `SET employee:1:lock NX EX 600` has no value, so Redis stores "NX" as the value and every caller succeeds.
10. **Stale or wrong vendor and model facts (rows 5.06, 5.09-5.12, 8.05, 8.06, 8.13, 7.01-7.03, 4.13).** Hyperbrowser has Profiles and Static IPs (not "ephemeral"). Browserless includes proxies, captcha solving and persisted sessions, with unit pricing (not "external proxies, flat pricing"). Claude 3.5 and 3.7 Sonnet are retired and the tool type is `computer_20241022`, not "computer-2024-10-22". CUA-S1-forms is a 706k-parameter forms research model that scored 29.3% out of catalogue. Steel Cloud now has a Computers API with exec, contradicting "Steel cannot run OS apps". Qwen2.5-VL, UI-TARS, Hermes 3 and DeepSeek-V3 are 2025-era picks that were never benchmarked here.

## Key

- Verdicts: **confirmed** (holds as stated), **partially** (a real thing with a wrong detail, scope or number), **wrong** (contradicted by source, docs or a run), **unverifiable** (no source, or needs a browser or container; those are marked "needs hands-on on a droplet").
- A few rows (1.01, 9.05, 9.08) are design opinions; they are scored on consistency with the fleet design, not on measurement.
- A table row is one claim. Where Gemini repeats a claim in several turns, the row lists all the line numbers.
