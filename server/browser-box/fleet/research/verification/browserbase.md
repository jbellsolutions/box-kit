# Verification: Browserbase dossier (adversarial)

- **Dossier under test:** `fleet/research/dossiers/browserbase.md`
- **Claims file:** `fleet/research/verification/claims/browserbase.json`
- **Verifier:** an independent adversarial agent, run on 2026-10-10. Spend: $0.00. No OpenRouter or Browserbase calls were made.
- **What was not done:** no containers, no browsers, no Docker, no hermes CLI.

## Method in brief

- **Primary pages re-fetched live on 2026-10-10** with `curl` (`.md` endpoints, `Accept: text/markdown` for the marketing pages). Each copy was diffed against the author's 2026-10-09 capture. All of the following are **byte-identical**:
  - Browserbase docs: `account/billing/plans`, `platform/identity/{proxies,verified-customization,overview,captcha-solving}`, `platform/browser/core-features/{contexts,session-metadata}`, `platform/browser/techniques/timezones`, `platform/browser/long-sessions/{timeouts,keep-alive}`, `platform/browser/security/ip-allowlisting`, `integrations/hermes-agent/setup`.
  - Marketing (`vendor-claim`): `www.browserbase.com/pricing`, `/changelog`, `/blog/identity`.
  - `/terms-of-service`.
  - Steel `docs.steel.dev/overview/pricinglimits`.
  - The live `https://docs.browserbase.com/llms.txt` page list equals the corpus page list (no new pages since capture).
- **Additional live fetches:**
  - Browserbase blog "How to rotate proxies automatically in a browser" (2026-09-01, `vendor-claim`).
  - AUP URL probes: `/aup`, `/acceptable-use-policy`, `/legal`, `/legal/*` all return **307 to sign-in**, as does every unknown path tried.
  - Two web searches.
- **Source read at the pinned commits:**
  - `bb-sdk-node@adef824` (2026-09-24).
  - `stagehand@1fc8849` (docs and extension).
  - Installed `stagehand` Python 4.2.0 **and** the npm `@browserbasehq/stagehand@4.2.0` `dist/` (a different route from the author's Python-only read).
  - npm `stagehand@3.7.3` `dist/` (for the v3 `cacheDir` alternative).
  - `browser-use` 0.13.11 installed.
  - `NousResearch/hermes-agent@5ba559c`, fetched fresh with `gh api`. It is identical to the author's copy, and the file is unchanged since `d76cce4` on 2026-10-08.
- **GitHub issues** were read with `gh`: authors, state, comment counts.
- **Raw spike outputs** were re-read: `out_offline_request_shapes.txt`, `out_offline_stagehand_launch.txt`, `out_cost_model.txt`.
- **Cost model:** recomputed by an independent script, not the author's.

Provenance tags: `official-docs`, `source-code`, `vendor-claim`, `third-party`, `inference`. The Correction column is filled only for partially-confirmed or refuted rows. Nuances on confirmed rows are listed under "Missed issues".

- **50 MB of proxy traffic per browser-hour.** Labelled "(given)", with no source in BRIEF.md, the dossiers or the repo docs. It conflicts with `scale-infra`'s "~27 GB/profile-month" (also unsourced). Every figure derived from it inherits the problem:
  - "proxy ≈ 5x browser time";
  - "74-83% of the bill is proxy";
  - $18 and $54 per profile-month;
  - $539, $1,619, $1,799, $5,399, $17,999 and $53,999 (Startup);
  - every Developer-plan cell;
  - every "Proxy GB/mo" cell;
  - both Steel Cloud columns.
- **12 h active window** behind every "peak concurrency" figure (2.5, 7.5, 8.3, 25, 83, 250), and so the Startup-fits/does-not-fit judgments.
- **Q2 "keepAlive no/yes/yes/yes" row as tabled.** The plans page has no such row. Three primary sources disagree (paid plans / Hobby+ / Startup+).

## Missed issues

1. **Built-in Browserbase proxies may rotate within a session, not just between sessions.**
   - Browserbase's own blog (2026-09-01, `vendor-claim`) says `proxies:true` "assign[s] and rotate[s] the IP for you" and "every request leaves through a rotating residential IP". It recommends static proxies for "Logged-in sessions".
   - So the "Browserbase on Developer/Startup" cost columns model a configuration that is unusable for the fleet's logged-in social profiles.
2. **The cost model's key driver is unsourced and contradicts a sibling dossier by 6-18x.**
   - At the `scale-infra` estimate (~27 GB/profile-month), Browserbase-proxy cost is about **$273-279 per profile-month** under either hours reading, versus the dossier's $18-54.
   - The "$3-5 per profile-month per daily hour" BYO figure is incomplete: it excludes the BYO static IP.
   - Measure real bytes per hour before any budget is set.
3. **Stagehand 4.2.0 `browser.close()` releases the Browserbase session even with `keep_alive=True`, and deletes the auto-uploaded extension.**
   - This contradicts the Stagehand docs' own keep-alive example (browser.mdx:947-961).
   - The dossier's login broker (keepAlive, human login, then reconnect) must never call `browser.close()` between steps.
   - The same is true in the npm 4.2.0 build.
4. **ToS clauses the dossier missed:**
   - "creating multiple accounts to avoid restrictions ... may result in immediate termination". The fleet cannot shard across Browserbase accounts to escape the concurrency cap or to limit suspension blast radius, so the single-account cap is hard.
   - "all use shall comply with ... the Platform's intended use cases. Use ... outside its intended purpose is prohibited".
   - "You may not transfer your account to anyone else without our prior written permission".
   - Under Session Recording: no "activity that is illegal, false or misleading".
5. **API keys are per project, and projects carry their own concurrency allotment.**
   - This allows coarse isolation (up to 5 projects on Startup), for example one project per client group.
   - The dossier says "no scoped keys". Per-*agent* keys still do not exist.
6. **Steel Cloud dedicated IPs cap at 25 self-serve.** Every "Steel Cloud + $5 IP" row (30 profiles and up) needs sales; only the 1,000 rows were footnoted.
7. **The Stagehand server cache serves only after a hit-count threshold of identical results.**
   - Its key includes page content and URL, and caching.mdx says "If the page content or structure changes, the action won't get a cache HIT". Feed-like pages are unlikely to hit.
   - Locator-scoped calls are never cached.
   - The v3 `cacheDir` fallback covers only `act()` and agent runs, not `extract()`/`observe()`.
8. **The keepAlive plan gate is inconsistent** across Browserbase docs (paid plans), the Node SDK (Hobby+) and Stagehand docs (Startup+). The proposed $20 Developer validation spike may not be able to test the keepAlive login flow.
9. **"No export" is self-serve only.**
   - Enterprise BYOS writes `contexts` artifacts (cookies, storage) to your own S3, Read/Write.
   - The fleet can also take its own CDP cookie and localStorage snapshot at session end as a partial backup.
   - So "backups are impossible" (§3) is overstated.
10. **Timezone override fragility** (`inference`, needs hands-on on a droplet). CDP `Emulation.setTimezoneOverride` lasts only as long as the DevTools session that set it. Workers and the Live View human-login session may expose the datacenter timezone. The fleet needs a check, not just a call.
11. **Provenance slips:**
    - BB-9's "hands-on" evidence (`REQUEST_RELEASE` after `ConnectionRefusedError`) is the `owns_source` failure-cleanup path, not `close()`. Source alone supports BB-9.
    - §Q1 attributes the `fingerprint` pass-through to Stagehand, but spike 1 used the Browserbase Python SDK.
    - 441,819 bytes is a multipart body size, not the extension size.
12. **The vendor positioning is mixed, not "identity, not evasion".** The pricing page of the same date advertises "a dedicated stealth research team" and "Stealth Mode: Advanced".

## Unverifiable without a paid key or hands-on on a droplet

Each of these is unverifiable without a paid key or hands-on work on a droplet:

- whether `GET /v1/sessions` crosses projects;
- whether BYO-proxy bytes are billed;
- whether built-in proxies rotate per request or per session;
- whether `timeout: 1800.0` (float) is accepted;
- whether `TIMED_OUT` sessions persist their Context;
- whether keepAlive works on Developer;
- Stagehand cache hit rates;
- the timezone leak via workers or Live View.
