## Numbers in the dossier with no source or measurement behind them

1. **"~30–60%" vs "30–55%".** §1 says the decider owns "~30–60% of browser actions"; §Q4 says "30–55%". These are estimates, and the two ranges are inconsistent.
2. **The §Q4 D / S1 / G table.** It has no measurement behind it:
   - (a) 40–60 / 35–55 / 0–10 / ~90–100%.
   - (b) 25–40 / 35–55 / 15–35 / ~65–85%.
   - (c) 15–30 / 30–45 / 30–50 / ~50–70%.
   - "≈1 copy-writing call per post".
3. **"1 call per ~2–3 s per active profile".** This is unmeasured.
   - The README's click step is 1.2–2.5 s.
   - jev-automation can add a second (verify) call per step.
4. **"10% concurrently active."** This is an assumed duty cycle.
5. **"~35–50 rps" and "~330–500 rps".** These are arithmetic on items 3 and 4, and they ignore the token cap (V-04).
6. **"≤1% wrong-action rate on reversible steps."** This is an example target with no source.
7. **"act when ≥0.8, treat as 'no' when ≤0.2".** This is an example band with no source.
8. **"100–200 element-choice and blocker cases".** This is a labeled-set size with no power or confidence-interval reasoning.
9. **"Approve a follow-up of about $0.001".** This was an estimate. Measured today, the Clef, Clef-flash and OpenAI calls cost $0.00035 together.
10. **The cost reference assumes a "1,000-token step".** That size is assumed. Measured 180-candidate steps are 4,911–6,217 tokens, about 5–6× more ($0.00021–0.00026 per step on Jev).
11. **"Perplexity screenshot step ~$0.00015".** This is derived from the cookbook's 7,300 tokens, which conflicts with the quickstart's ~1,000 tokens per megapixel (V-14).
12. **`max_latency_ms: 2000` and `max_cost_usd: 0.001`** in the `/decide` example. These are illustrative only.

## Missed issues (what the dossier missed or got wrong)

1. **Jev's token cap, not its request cap, binds for real steps (design-changing).**
   - A step with 180 candidates and 3 questions is 4,911 tokens (lean strings) to 6,217 tokens (descriptive strings), which gives about 16–20 steps/s under 100K tok/s.
   - The limits moved in opposite directions between 2026-09-17 and 2026-10-10: requests rose 4×, tokens fell 60%.
   - The §Q5 budget ("fits Jev alone") fails at the 10% duty cycle once pages are dense.
2. **The same open weights give different numbers on different hosts (design-changing).**
   - Clef-flash blocker confidence was 0.43 on Cloudflare and 0.74 on PrimeIntellect. Each host was deterministic across repeats.
   - Unpinned OpenRouter calls went to PrimeIntellect.
   - Calibration and thresholds must key on the serving provider, and the provider must be pinned and logged.
3. **OpenAI limits are not a blank (possibly design-changing).**
   - The gpt-6-luna page the author already had on disk lists tier limits: 5,000–30,000 RPM and 2M–180M TPM.
   - The token caps decide it, not RPM. At a ~6K-token step, Build (2M TPM ≈ 33K tok/s) gives about 5 steps/s, below Jev. Launch gives about 27 steps/s. Only Grow (180M TPM, 500 rps) covers the full-concurrency case.
   - If Grow-tier limits apply to `/v1/decisions`, OpenAI could be the high-throughput backbone, at 2.4× Jev's price per token. It is not confirmed that these limits apply to Decisions.
   - Confirming the limits needs an OpenAI key or a direct question to OpenAI.
4. **Build-vs-reuse for the replay tier.**
   - In Stagehand v4, `act(Action)` is the documented replay primitive: no inference, no snapshot, no settle wait. The fleet stores and keys `Action` objects.
   - Stagehand 3.7.3 still ships a local `cacheDir` / `ActCache`.
   - On Browserbase, v4's server cache is gated per project by a server-side flag, so it is not guaranteed even there.
5. **Jev silently accepts image parts.**
   - It returns 200 and bills the data URL as text, so a misrouted screenshot step yields a plausible number with no error.
   - The `/decide` router must enforce modality per provider.
6. **There are no rate-limit headers from Jev or OpenRouter on decision calls.**
   - Limiting must be client-side, using the documented limits plus 429 handling.
   - Perplexity documents `x-ratelimit-*`; Jev does not send them.
7. **Option-order bias is missing from the jaggedness summary.**
   - TypeSafe lists 9 failure modes; the dossier lists 7. It drops "Contradictory instructions and criteria" and "Choice option order".
   - The dropped option-order entry says jev-1.13 "leans toward the option that comes first".
   - DOM-ordered candidate lists put headers and navigation first. The README's Wikipedia miss (a link above the results) is consistent with this bias.
   - Shuffle the candidates, or ask in both orders, for low-margin production steps, not only during calibration.
8. **How OpenRouter returns an OpenAI `refusal` is unknown.**
   - OpenRouter's `DecisionsResponse` schema has only noul, choice and score.
   - `/decide` must treat unknown answer types and missing answers as an escalation, not a crash.
9. **`selfHeal` turns `act(Action)` back into an LLM call.**
   - When `selfHeal` is on, a broken selector triggers `getActionFromLLM`. The default is off; keep it off on the decider path.
   - The xpath selector format is already answerable from source: `xpath=<path>`.
10. **`rerun_history` always makes one LLM call, for the summary.** So it is not an LLM-free replay tier as written.
11. **The fleet's own latency datasets disagree.**
    - Direct calls: 140–330 ms.
    - An older local tool's production path: medians 443 and 487 ms, close to Cloudflare's 524 ms.
    - The README's 8.8 s outlier would have hit jev-automation's 8 s timeout.
12. **`confidence` means different things per provider.**
    - Clef-flash: top probability 0.69, confidence 0.43. Jev: 0.92 and 0.91. OpenAI: 0.79 and 0.76.
    - A shared confidence threshold, or even a shared margin rule, is not portable across providers.
13. **Smaller corrections.**
    - Provider pinning also works on `/api/v1/systemone`.
    - Decider, not Clef-flash, is the cheapest decider.
    - Tokenizers differ by up to 17% on the same body.
    - The Workers AI limits page predates Clef's launch.
    - "Only 1 of 4 verified through OpenRouter" is now 4 of 4.
